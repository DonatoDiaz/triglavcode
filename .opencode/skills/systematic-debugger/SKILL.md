# Systematic Debugger

Методологическая отладка для сложных багов, когда быстрые правки не работают. Дополняет `/heal`; используй, когда первопричина неочевидна.

## Рабочий процесс (цикл)

1. **Воспроизведи в минимуме**
   - Наименьшая команда/скрипт, который стабильно даёт баг.
   - Зафиксируй **точный** вход, ожидаемый выход и фактический. Сфото/сохрани ошибку целиком (трассировку, а не 1-2 строки).

2. **Читай код, а не только ошибку**
   - Пройди путь данных от источника к точке сбоя.
   - Ищи предположения, нарушенные данными: типы, `null`/`undefined`, индексы, диапазоны, временные зоны, регистр.
   - Не «псевдофикси по памяти» — подтверди чтением кода и данных.

3. **Одна гипотеза → один эксперимент**
   - Сформулируй гипотезу причинности: «баг происходит потому, что X → Y → Z».
   - Измени ровно одну вещь (патч/изоляция/пример). Никогда не меняй 2+ одновременно.
   - Перезапусти воспроизведение; запиши результат (успех/частично/не изменилось).

4. **Бинарный поиск**
   - При большом вводе/истории — дели пополам (git bisect, закомментировать блоки, уменьшать вход) до минимального триггера.

5. **Разделяй симптомы и причину**
   - Каждый симптом отследи до точки порождения. Одна ошибка в логе ≠ одна корневая причина.

6. **Зафиксируй**
   - После корня: напиши регрессионный тест, который падал до фикса.
   - Разбор (миследящие сообщения, неочевидная причина) — кандидат в `/learn`.

## Анти-паттерны
- Множественные правки между запусками.
- «Пальцем в небо» без гипотезы причинности.
- Игнор реального стека в пользу «это просто race» и т.п.
- Сдаться после 1-3 попыток без переоценки гипотезы.

## Связь с другими инструментами
- `/heal` — быстрый цикл починки для понятных ошибок; этот скилл — для непрояснённой первопричины.
- `/learn` — после успеха сохрани неочевидные разборы.
