description: Gated PR review: проверка гигиены перед push/PR
---

Проведи ревью текущей ветки перед созданием PR. Не комить праве без явного разрешения.

## Шаги

1. **Собери контекст**: `git diff <base>...HEAD --stat`, затем полный diff по изменённым файлам. Если base не задан — уточни (default: origin/dev).

2. **Чек-гиены** (каждый пункт — явный вердикт pass/fail):
   - Секреты и ключи (`.env`, токены, пароли, приватные ключи) не попали в diff
   - Нет `console.log`/`debugger`/отладочного мусора
   - Нет конфликтных маркеров (`<<<<<<<`, `>>>>>>>`)
   - Нет болванок (`TODO`, `FIXME`, зашитых путей `/path/to/`, `example.com`)
   - Нет генерации случайных/бессмысленных файлов, нет бинарников в git
   - Изменения соответствуют стилю кодовой базы
   - Затрагиваемые тесты/typecheck покрывают изменения (укажи, какие)

3. **Суть**: что меняется, зачем, есть ли регрессии. Одно-два предложения о рисках.

4. **Вердикт** (один из):
   - `🟢 approve` — можно пушить как есть
   - `🟡 changes` — блокирующих нет, но нужно (список мелочей)
   - `🔴 request-changes` — есть блокер из п.2; не пушить до исправления

## Правила
- Никогда не пушить по своей инициативе во время ревью.
- При `request-changes` покажи точные файлы/строки с проблемой.
