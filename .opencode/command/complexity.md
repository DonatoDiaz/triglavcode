Оцени сложность задачи до начала работы и порекомендуй стратегию.

## Шаги

1. **Распарси задачу** — что требуется, какие файлы/системы затрагиваются.

2. **Оцени по осям** (каждая 1-5):
   - Число модулей/областей кодовой базы
   - Число незаданных требований (неоднозначностей)
   - Риск (миграции, БД, публичные API, безопасность, ломающие изменения)
   - Зависимость от внешних систем (сеть, сервисы, железа, ключи)

3. **Сумма → вердикт**:
   - `4-6` — **trivial**: сразу выполнять
   - `7-11` — **medium**: план до кода (короткий, 3-5 шагов) + сразу выполнять
   - `12-15` — **complex**: полный план с iterate/review; в идеале отдельный plan-агент перед кодом
   - `16+` — **very complex**: разбить на фазы (см. `/parallel`), предварительно показать план на утверждение

4. **Результат**: балл по осям, вердикт, рекомендация (что сделать первым). Ничего не выполняй без явного подтверждения, если вердикт `complex+`.
